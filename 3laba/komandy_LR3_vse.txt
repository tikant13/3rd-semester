ЛР3 — ВСЕ КОМАНДЫ ДЛЯ ЗАПУСКА И СКРИНШОТОВ В ОТЧЁТ
Выполнять в терминале Ubuntu. Каждый блок можно копировать целиком.

============================================================
1. C++ — ПЕРЕЙТИ В ПАПКУ
============================================================
cd ~/3st-semester/3laba/LR3_CPP

============================================================
2. C++ — СЕРИАЛИЗАЦИЯ (СКРИНШОТ ДЛЯ РИСУНКА 6)
============================================================
# Сначала собери GoogleTest (если ещё не собран):
bash coverage.sh google

# Запусти только тесты сериализации:
./build/google/test_google --gtest_filter='SerializationTest.*'

# Сделай скриншот строк [ RUN ], [ OK ], [ PASSED ].

============================================================
3. C++ — ТЕСТЫ И ПОКРЫТИЕ (РИСУНКИ 8, 9, 10)
============================================================
# Рисунок 8 — Boost.Test:
bash coverage.sh boost

# Рисунок 9 — GoogleTest:
bash coverage.sh google

# Рисунок 10 — Catch2:
bash coverage.sh catch

# Скриншот каждого блока: конец вывода с PASSED/No errors
# и lines / functions / branches. Скрипт очищает старые данные покрытия.

============================================================
4. C++ — ОТКРЫТЬ HTML-ОТЧЁТЫ (ЕСЛИ НУЖНЫ СКРИНШОТЫ ТАБЛИЦ)
============================================================
xdg-open build/boost/coverage.html
xdg-open build/google/coverage.html
xdg-open build/catch/coverage.html

============================================================
5. C++ — ДЕМОНСТРАЦИЯ ПРОГРАММЫ И СЕРИАЛИЗАЦИИ
============================================================
g++ -std=c++17 main.cpp array.cpp linkedList.cpp doublyList.cpp stack.cpp Queue.cpp Rbtree.cpp Chaintable.cpp Cuckootable.cpp -o dbms

# Текстовый файл:
./dbms --file data.txt --query 'SPUSH mystack first'
./dbms --file data.txt --query 'SPUSH mystack second'
./dbms --file data.txt --query 'SPEEK mystack'

# Бинарный файл:
./dbms --file data.bin --format binary --query 'SPUSH mystack first'
./dbms --file data.bin --format binary --query 'SPUSH mystack second'
./dbms --file data.bin --format binary --query 'SPEEK mystack'

============================================================
6. C++ — БЕНЧМАРКИ (ЕСЛИ НУЖНО ДЛЯ ОТЧЁТА)
============================================================
# Если библиотека не установлена: sudo apt install libbenchmark-dev
mkdir -p build
g++ -std=c++17 -O2 -I. benchmark.cpp array.cpp linkedList.cpp doublyList.cpp stack.cpp Queue.cpp Rbtree.cpp Chaintable.cpp Cuckootable.cpp -o build/benchmark -lbenchmark -pthread
./build/benchmark

============================================================
7. Go — ПЕРЕЙТИ В ПАПКУ
============================================================
# Работает, если папка называется LR3_Go или go:
cd ~/3st-semester/3laba
if [ -d LR3_Go ]; then cd LR3_Go; else cd go; fi

============================================================
8. Go — ЗАВИСИМОСТИ, СБОРКА И ВСЕ ТЕСТЫ
============================================================
go mod tidy
go build ./...
go test ./... -v
go test -race ./...
go vet ./...

============================================================
9. Go — ТЕСТЫ СЕРИАЛИЗАЦИИ (СКРИНШОТ ДЛЯ РИСУНКА 7)
============================================================
go test ./ds -run 'Serialization' -v

# Сделай скриншот результатов PASS и названий тестов сериализации.

============================================================
10. Go — ПОКРЫТИЕ КОДА (СКРИНШОТ ДЛЯ РИСУНКА 11)
============================================================
go test ./... -coverprofile=coverage.out
go tool cover -func=coverage.out

# HTML-отчёт (если нужен отдельный скриншот):
go tool cover -html=coverage.out -o coverage.html
xdg-open coverage.html

============================================================
11. Go — БЕНЧМАРКИ
============================================================
go test ./ds -run '^$' -bench=. -benchmem

============================================================
12. Go — ФОРМАТИРОВАНИЕ И СТАТИЧЕСКАЯ ПРОВЕРКА
============================================================
gofmt -l ds/*.go
go vet ./...

============================================================
ВАЖНО
============================================================
- Команды для C++ (пункты 2–6) выполняй из LR3_CPP.
- Команды для Go (пункты 8–12) выполняй из LR3_Go или go.
- Для рисунков с тестированием снимай реальный вывод, не только команду.
- Если Go пишет «no tests to run», проверь названия: go test ./ds -list .
- Вывод покрытия Go может отличаться от C++ — это разные метрики.
- Скрипт coverage.sh выводит реальное текущее покрытие и сохраняет HTML в build/.
