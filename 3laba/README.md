# ЛР3 — задание 1, классы C++

Основа: классы Array, linkedList, DoublyList, Queue, Stack, RBTree из 1laba;
ChainTable и CuckooTable из 2laba/task6.1. Имена, алгоритмы и оформление сохранены.
Это C++-часть задания 1. Версия на Go/Rust, тестовые фреймворки, покрытие,
benchmark и сериализация ЛР3 в эту папку не входят.

## Что изменено

- Внешние `struct` заменены на `class`. Вложенные `Node` оставлены структурами
  внутри private: снаружи получить доступ к ним нельзя.
- Методы, которые не меняют объект, помечены `const` в .h и .cpp.
- Копирующий конструктор и присваивание запрещены через `= delete`.
  Иначе два объекта владели бы одними указателями и оба вызвали delete.
  Передавать объекты в функции нужно по ссылке. Глубокое копирование пока не реализовано;
  перемещение также недоступно.
- Для списков, очереди, стека и дерева явно оставлен конструктор `= default`:
  поля уже инициализируются в объявлениях. Он нужен после объявления
  удалённого копирующего конструктора, чтобы работало `Stack stack;` и т. п.
- По замечаниям Cppcheck добавлен `next = nullptr` в узел односвязного списка,
  строка в Array::Set передаётся через `const string&`.
- Восстановлен main из ЛР1 с --file и --query; добавлены команды хеш-таблиц.
- Makefile запускает только линтер.

`struct` и `class` в C++ отличаются доступом по умолчанию (в том числе при
наследовании). При явно заданных private/public замена сама по себе не меняет
работу методов. Конструкторы и деструкторы в исходном коде уже были.

## Проверка линтером

Makefile содержит только цель lint. Команды `make` и `make lint` запускают
Cppcheck; сборки, запуска программы и удаления файлов в Makefile нет.
Нужны make и отдельно установленный Cppcheck.

```sh
make lint
```

## Ручная сборка и запуск

Из папки cpp:

```sh
g++ -std=c++17 -Wall -Wextra -Wpedantic *.cpp -o dbms
./dbms --file file.data --query 'SPUSH mystack item'
./dbms --file file.data --query 'SPOP mystack'
./dbms --file file.data --query 'QPUSH myqueue element'
./dbms --file file.data --query 'QPOP myqueue'
./dbms --file file.data --query 'TINSERT mytree 10'
./dbms --file file.data --query 'ISMEMBER mytree 10'
./dbms --file file.data --query 'HSET myhash key value'
./dbms --file file.data --query 'HGET myhash key'
./dbms --file file.data --query 'CSET cuckoo key value'
./dbms --file file.data --query 'PRINT cuckoo'
```

Каждый запуск выполняет одну команду. При добавлении новая именованная структура
создаётся автоматически; отсутствующий файл создаётся при первом успешном изменении.
Чтение не перезаписывает файл. Одно имя нельзя использовать для разных типов.
Команды и формат строк M/F/L/S/Q/T перенесены из ЛР1.

| Тип | Команды (после команды всегда имя структуры) |
| --- | --- |
| Массив | MCREATE; MPUSH значение; MINSERT индекс значение; MGET индекс; MDEL индекс; MSET индекс значение; MLEN |
| Односвязный список | FPUSH/FPUSHTAIL/FPUSHHEAD значение; FPUSHBEFORE/FPUSHAFTER цель значение; FDEL/FDELVAL значение; FDELHEAD/FDELTAIL; FDELBEFORE/FDELAFTER цель; FGET индекс; FGETHEAD/FGETTAIL; FFIND значение |
| Двусвязный список | Те же команды списка с префиксом L вместо F |
| Стек | SPUSH значение; SPOP; SPEEK |
| Очередь | QPUSH значение; QPOP; QPEEK |
| Дерево | TINSERT/TDEL/TGET/ISMEMBER целый_ключ; TINORDER; TPREORDER; TPOSTORDER; TBFS |
| Метод цепочек | HSET ключ значение; HGET ключ; HDEL ключ |
| Кукушка | CSET ключ значение; CGET ключ; CDEL ключ |
| Любая структура | PRINT имя |

SPOP и QPOP выводят и удаляют элемент. HSET/CSET обновляют значение существующего
ключа. HDEL/CDEL выводят удаляемое значение. Новые строки файла имеют вид
`H имя ключ значение ...` и `C имя ключ значение ...`. Для них добавлены методы
ToString у хеш-таблиц; порядок пар после восстановления может изменяться.

Как в исходном интерфейсе ЛР1, имена, ключи и строковые значения — отдельные
слова без пробельных символов; пустые значения не поддерживаются. Внешние кавычки
в примерах объединяют всю команду в один аргумент оболочки.
Текстовый файл должен быть корректным, созданным программой; полной проверки
повреждённых файлов и восстановления после прерванной записи нет.
Это ещё не закрывает отдельное требование ЛР3 о бинарной сериализации.

Для компиляции только одного класса без main можно использовать
`g++ -std=c++17 -c stack.cpp` (получится stack.o, не запускаемая программа).

## Сохранённые ограничения исходного интерфейса

Массив и списки возвращают пустую строку при неверном индексе (DoublyList
дополнительно печатает ошибку). Пустую строку и ошибку по результату At не различить.
Обе хеш-таблицы не принимают пустой ключ. У ChainTable ключ не должен содержать
табуляцию: она используется как разделитель ключа и значения.
RBTree::Load предназначен для восстановления корректно сохранённого дерева
в прямом обходе с исходными цветами. Для обычного добавления нужен Insert;
произвольные вызовы Load могут нарушить свойства красно-чёрного дерева.
ToString и Load перенесены из ЛР1, это ещё не реализация задания 3 ЛР3.

## Выполненные проверки

Сборка g++ с -Wall -Wextra -Wpedantic и Cppcheck проходят.
После восстановления CLI проверены 383 отдельных запуска: все восемь контейнеров,
сохранение между запусками, обновление/удаление ключей, 80 пар в каждой
хеш-таблице, PRINT, чтение старого формата ЛР1. Ещё четыре неверные команды
отклонены без изменения файла.
Отдельная проверка операций всех контейнеров прошла с AddressSanitizer и
UndefinedBehaviorSanitizer: в том числе 500 записей в каждой хеш-таблице и
4000 случайных вставок/удалений дерева со сравнением поиска и размера со std::set.
Проверка утечек LeakSanitizer отключена из-за ограничения среды (ptrace).
Это не тестовое покрытие по заданию 2 и не проверка всех инвариантов RBTree.
